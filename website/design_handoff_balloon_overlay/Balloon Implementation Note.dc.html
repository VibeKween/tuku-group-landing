TUKU GROUP — Implementation Note

Balloon overlay for tukugroup.com

Deliverable: site/tuku-balloon.js — dependency-free, no build step, ~6 KB. Ported from the prototype in TUKU Landing Balloon.dc.html; motion, physics and label styling are identical.

1 — Production mount

The prototype composited the balloon over an iframe of the live site. That was a preview device only. In production the script appends its own fixed-position overlay to <body> — no iframe, no wrapper element, no change to existing markup. Drop one tag at the end of the site template:

<script src="/tuku-balloon.js" defer
        data-image="/assets/balloon-smiley.png"
        data-href="/clients"></script>

The field is pointer-events: none except on the balloon and its label, so nav, links and scroll underneath behave normally. Tunable via data attributes: data-rise-delay, data-rise-duration, data-balloon-size, data-breeze, data-label, data-z-index. Set data-auto="false" and call TukuBalloon.mount({…}) yourself if a router needs to control timing; TukuBalloon.unmount() tears it down.

2 — Destination URL

Delegated to implementation. The prototype points at Client Archive.dc.html, a local file. The production path will be determined from the repo's existing URL conventions — how ideas/, signals/, studio.html and book/ are named and structured — rather than fixed here.

No gate. The client page is public. No auth, no server-side protection. The passphrase interaction inside the archive is a design device within the page, not access control. Remaining question is only whether the page appears in sitemap.xml — "clients only!" reads as unlisted-but-public, so likely noindex, not excluded outright.

3 — Reduced motion

Handled. Under prefers-reduced-motion: reduce the script mounts a static variant: the balloon appears immediately in its resting position, top-right, with the label intact and every animation disabled — no rise, no bob, no sway, no gradient cycle, no drag physics. The entry point is preserved; only the motion is dropped. Pass respectReducedMotion: false to override.

4 — Persistence

Open — pick one. Default today is every visit: the balloon rises on each page load. Alternatives are built in but off:

Every load
Current default. Highest discovery; can read as repetitive for frequent visitors.
Once per session
Add data-once="true". Uses sessionStorage, so no cookie banner implication.
Landing page only
Include the tag on the home template only. Simplest, and keeps the balloon a front-door gesture rather than site furniture.

Recommendation: landing page only, every load. The rise is the point; suppressing it costs more than the repetition does.

5 — Before it ships

  • Upload balloon-smiley.png to the asset path and confirm the transparent PNG survives whatever image pipeline the host runs.
  • Confirm z-index against any existing fixed nav or cookie banner; default is near the top of the stack.
  • Mobile check: the balloon caps at 44vw and keeps a right-edge inset for the label, but verify against the real header at 375px.
  • Decide the destination path and the gate (item 2) — that is the last blocker.
